nablr exposes 36 MCP tools. Most run entirely locally (no network call, no key
required); a few dispatchers group related behavior behind an `action`,
`target`, or `event` parameter instead of one tool per verb. Every tool name
and action value on this page is read directly from the server's tool
registry — see [Usage](#usage) for how that's kept honest.

## <Icon icon="scan-search" /> Quality scanners — `scan`

<Card title="scan(target, directory, ...)" icon="scan-search">
  One dispatcher tool, 12 targets. `health` is the primary entry point — runs
  every scanner and can trigger remediation.
</Card>

| `target` | What it does | Example |
|---|---|---|
| `health` | Unified health report across all quality dimensions; primary entry point | `scan(target="health", directory=".")` |
| `debt` | TODOs, bare exceptions, missing types, long functions | `scan(target="debt", directory="src/")` |
| `dead_code` | Unused functions, classes, imports | `scan(target="dead_code", directory="src/")` |
| `complexity` | Cyclomatic + cognitive complexity per function | `scan(target="complexity", files="src/app.py")` |
| `external` | Env vars, API clients, external URLs | `scan(target="external", directory=".")` |
| `regression` | Regression risk on changed files | `scan(target="regression", files="src/app.py")` |
| `docs` | Missing or stale documentation | `scan(target="docs", directory="src/")` |
| `ai_patterns` | AI-generated code smells, test anti-patterns | `scan(target="ai_patterns", file_path="src/app.py")` |
| `security` | Hardcoded secrets, injection risks, insecure patterns | `scan(target="security", directory=".")` |
| `codemap_freshness` | Stale `CODE_MAP.md` vs. current file tree | `scan(target="codemap_freshness", directory=".")` |
| `migration_readiness` | Assess a module's readiness for a planned migration | `scan(target="migration_readiness", directory="src/")` |
| `full_suite` | Bounded run of the Mandatory Tooling gate (ruff/pyright/lint/tsc/build) | `scan(target="full_suite", directory=".")` |

Pass `mode="migration"` with `target="health"` to activate migration-intent
detection. Pass `diff_scope=true`/`false` to force diff-only or whole-repo
scope on `health`/`security`/`full_suite` (auto-resolved from story context
when omitted).

## <Icon icon="wand-sparkles" /> Remediation — `remediate`

<Card title="remediate(action, ...)" icon="wand-sparkles">
  Turns a `scan` report into an autonomous or approved fix plan.
</Card>

| `action` | What it does | Example |
|---|---|---|
| `start` | Parse scan output, classify violations into tiers, return a plan | `remediate(action="start", scan_output="<scan JSON>")` |
| `state` | Show current remediation session progress | `remediate(action="state", session_id="...")` |
| `execute` | Return the ordered work plan for a tier | `remediate(action="execute", tier="tier1")` |
| `approve` | Approve a Tier 2 batch (requires human sign-off) | `remediate(action="approve", session_id="...")` |
| `defer` | Defer one violation to `TECH_DEBT.md` instead of fixing | `remediate(action="defer", violation_id="...", reason="...")` |
| `update` | Mark violations `auto_fixed`/`failed` after fixes land | `remediate(action="update", violation_ids=["..."], status="auto_fixed")` |
| `complete` | Close the session after PR Reviewer gate passes | `remediate(action="complete", session_id="...")` |

## <Icon icon="workflow" /> Workflow orchestration — `workflow`

<Card title="workflow(action, story_id, ...)" icon="workflow">
  The SDLC state machine: init a story, advance phases, run parallel gates, merge back.
</Card>

| `action` | What it does | Example |
|---|---|---|
| `init` | Start tracking a story through the SDLC | `workflow(action="init", story_id="STORY-001", epic_id="EPIC-001")` |
| `list` | List all tracked stories | `workflow(action="list")` |
| `state` | Current phase, blockers, pending artifacts | `workflow(action="state", story_id="STORY-001")` |
| `next` | Auto-suggest the next agent based on state | `workflow(action="next", story_id="STORY-001")` |
| `parallel_start` | Open a parallel-track phase (e.g. QA Gate, Verification) | `workflow(action="parallel_start", story_id="STORY-001")` |
| `parallel_complete` | Signal one parallel-track agent's completion | `workflow(action="parallel_complete", story_id="STORY-001", agent="tester", status="passed")` |
| `fix_flow` | Start a fix-flow session, activates `forensic_engineer` | `workflow(action="fix_flow", file_path="src/app.py", error_description="500 on login")` |
| `complete_fix_flow` | Close a fix-flow session, activates `scrum_master` | `workflow(action="complete_fix_flow", story_id="FIX-...")` |
| `complete` | Close out a finished story's workflow | `workflow(action="complete", story_id="STORY-001")` |
| `validate_story_file` | Confirm a story markdown/JSON pair exists and parses | `workflow(action="validate_story_file", story_id="STORY-001")` |
| `validate_and_advance` | Validate the current phase's artifact and advance | `workflow(action="validate_and_advance", story_id="STORY-001", next_phase="developer")` |
| `merge_back` | Merge a story's isolated worktree branch back and clean up | `workflow(action="merge_back", story_id="STORY-001")` |
| `repair` | Repair a corrupted/inconsistent workflow state record | `workflow(action="repair", story_id="STORY-001")` |
| `revert_phase` | Revert to the adjacent predecessor phase | `workflow(action="revert_phase", story_id="STORY-001", phase="developer")` |

`override=true` on `validate_and_advance` forces a non-adjacent phase jump
(logs an L2 escalation; never bypasses artifact/blocker checks).

## <Icon icon="user-check" /> Agent control — `agent`

<Card title="agent(action, name, ...)" icon="user-check">
  List, activate, identify, or gate-check a persona.
</Card>

| `action` | What it does | Example |
|---|---|---|
| `list` | List all available agent personas, numbered | `agent(action="list")` |
| `activate` | Activate an agent by name or number (this is the replacement for the old `set_active_agent`) | `agent(action="activate", name="developer")` |
| `identify` | Suggest which agent best fits a free-text task description | `agent(action="identify", context="fix a 500 error on login")` |
| `check` | Check whether an agent's activation prerequisites are met, without activating it | `agent(action="check", name="architect")` |

`force=true` on `activate` bypasses the artifact-prerequisites gate (logs an
escalation). `story_id` on `activate`/`check` gates against a specific story
instead of the session's active-story pointer.

## <Icon icon="diagram-project" /> Session context & knowledge graph — `context`

<Card title="context(action, ...)" icon="diagram-project">
  Session-scoped notes plus a queryable knowledge graph of the codebase and story history.
</Card>

| `action` | What it does | Example |
|---|---|---|
| `add` | Add a session context entry | `context(action="add", layer="story", entry_type="decision", content="...", identifier="STORY-001")` |
| `get` | Read session context entries | `context(action="get", story_id="STORY-001")` |
| `clear` | Clear session context | `context(action="clear", story_id="STORY-001")` |
| `graph_add` | Add a node to the knowledge graph | `context(action="graph_add", node_type="decision", content="...", story_id="STORY-001")` |
| `graph_related` | Get nodes related to a given node | `context(action="graph_related", node_id="src/app.py")` |
| `graph_chain` | Get the causality chain for a story | `context(action="graph_chain", story_id="STORY-001")` |
| `graph_data` | Export raw graph data | `context(action="graph_data", format="json")` |
| `graph_populate` | Populate the graph from the codebase (AST + git + optional LLM) | `context(action="graph_populate", directory=".", levels="L1,L2")` |
| `graph_query` | Full-text query over the graph | `context(action="graph_query", term="auth")` |
| `graph_subgraph` | Extract a subgraph around a node | `context(action="graph_subgraph", node_id="src/app.py", depth=2)` |
| `graph_html` | Render an interactive HTML graph viewer to `nablr-reports/graph.html` | `context(action="graph_html", directory=".")` |
| `graph_watch` | Start a file watcher that incrementally updates the graph | `context(action="graph_watch", directory=".")` |
| `graph_watch_stop` | Stop a running graph file watcher | `context(action="graph_watch_stop", directory=".")` |

`manage_context(action, ...)` is a lighter standalone tool exposing only the
`add`/`get`/`clear` behavior above, for callers that don't need the graph.

## <Icon icon="chrome" /> Browser / E2E testing — `browser`

<Card title="browser(action, ...)" icon="chrome">
  nablr cannot drive a browser itself — it hands out one conceptual test
  step at a time; the calling agent runs it via its own Playwright MCP tools
  and reports the real outcome back.
</Card>

| `action` | What it does | Example |
|---|---|---|
| `check` | Detect whether a real Playwright MCP is available this session | `browser(action="check")` |
| `write_tests` | Register conceptual E2E test cases for a story | `browser(action="write_tests", story_id="STORY-001", test_cases_json="[...]")` |
| `execute` | Get the next conceptual test step to run | `browser(action="execute", story_id="STORY-001", test_id="TC-001")` |
| `report_step` | Report a step's real outcome back | `browser(action="report_step", story_id="STORY-001", success=true, duration_ms=420)` |
| `verify` | Verify all registered test cases completed | `browser(action="verify", story_id="STORY-001")` |

| Tool | What it does | Example |
|---|---|---|

| `defer_e2e_testing` | Formally defer E2E testing to `TECH_DEBT.md` (requires `confirmed=true` after user approval) | `defer_e2e_testing(story_id="STORY-001", reason="no UI surface", confirmed=true)` |

## <Icon icon="terminal" /> Usage

Tools are available automatically once nablr is connected. Invoke them naturally:

```
Scan this directory for technical debt
```

```
Generate a codemap for src/
```

```
What's the current workflow state for STORY-042?
```

Every tool name and action value on this page is checked in CI against the
live MCP tool registry (`nablr.server.mcp.list_tools()`) — if a tool is
renamed or an action added or removed, the check fails until this page is
updated to match.
